# 점검과 복구

- 최초 `loom task run`은 sandbox에서 develop.lock을 작성할 수 없어 실패했다. 같은 Loom 명령에 브랜치 준비·세션 시작 권한을 요청한 뒤 정상 복구했다. 사용자 변경을 되돌리거나 정책을 우회하지 않았다.
- 기존 사이트의 /resume 403은 참고 자료의 알려진 제한이다. 이 Task 범위에서는 서버를 수정하지 않고 사용자 PDF의 내용만 활용한다.
- 원문 날짜·블로그 주소 불일치는 명세 표와 안전한 생략 기본안으로 처리했다. 로컬 구현을 막는 미해결 장애는 없다.
- Loom의 Job 목표 복합성 경고는 한 포트폴리오의 설계·구현·검증·배포를 나열한 목표에서 발생했다. 동일 사용자 목표이므로 임의의 새 Job으로 분리하지 않는다.
